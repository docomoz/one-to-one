# Как мы работаем

Шпаргалка для людей. Правила для Claude лежат в `CLAUDE.md`.

## Цикл одной задачи
Доска задач: https://github.com/users/DariaPrishchepa/projects/1

1. На доске берёшь верхнюю задачу из **Todo**, у которой закрыты зависимости. Ставишь себя assignee и переносишь в **In progress**. Теперь напарник видит, что ты её делаешь.
2. Открываешь **новый чат** Claude Code в папке проекта и пишешь: «Задача #N. Сделай её по нашему процессу».
3. Claude делает `git pull`, создаёт ветку, пишет тесты и код, коммитит маленькими шагами.
4. Когда готово: `/code-review`, исправить найденное, push, PR по шаблону.
5. GitHub сам гоняет проверку `ci` (сборка и тесты). Вливаем только зелёный PR: красный сначала чиним. Если GitHub пишет, что ветка отстаёт от `main` (out-of-date), жмём **Update branch** и ждём, пока `ci` снова станет зелёной: так проверяем PR вместе со всем, что уже влили.
6. Claude сам вливает PR в `main` (squash), задача в **Done**. Ревью напарника не ждём: обсуждаем голосом, а напарнику достаточно прочитать описание PR.
7. Чат закрываешь, следующая задача в новом чате.

## Почему так
- **Новый чат на задачу**: длинный чат забивается старым контекстом, Claude хуже соображает и тратит больше токенов. Всё нужное лежит в файлах и в issue.
- **Ветка и PR**: двое не мешают друг другу, а в `main` всегда рабочая версия.
- **Push не после каждой правки**: коммит сохраняет шаг локально, push отправляет ветку на GitHub. Пушим, когда шаг готов или перед перерывом, чтобы ничего не потерять.
- **Описание PR**: это записка напарнику. Даже без ревью он прочитает её, когда будет делать соседнюю задачу.
- **Авто-ревью вместо человека**: `/code-review` ловит баги до merge, а проверка `ci` на GitHub не даёт влить то, что не собирается или ломает тесты.

## Полезные команды Claude Code
- `/clear`: начать с чистого контекста в том же окне.
- `/code-review`: ревью текущих изменений перед PR.
- `/compact`: сжать длинный чат, если задача ещё не закончена.
