# Офлайн-каталог фильмов (#55): дизайн

**Зачем:** подбор фильма не должен ломаться ни без сети, ни когда кончились 200 запросов в день к Кинопоиску (лимит общий для обоих телефонов). В обоих случаях колода собирается. Подробности задачи: issue #55.

Ниже всё обсуждено с Максюшей («заебись» на описание в чате). Что помечено **решение Claude**, придумал Claude, когда описывал детали.

## Цели
- Колода собирается в режиме полёта и при ошибке 401 / 403 / лимите: из списков и из каталога на телефоне по жанрам настроения.
- Каталог на телефоне растёт сам: всё, что пришло от Кинопоиска, запоминается.
- Догрузка новых фильмов не чаще раза в день и не больше 2 запросов, без дублей.
- Базовый `movies.json` обновляется скриптом, который запускают руками (например, раз в месяц).

## Не цели
- Постеры без сети: в файле только ссылки, показываются те, что уже загружены (кэш `URLSession`).
- «Похожие» без сети.
- Синхронизация каталога между телефонами: это не данные пары, в iCloud не едет.

## Антицели
- Колода стала медленнее или тратит больше запросов, чем сейчас.
- Один фильм дважды в колоде.
- Каталог на телефоне раздувается без предела.

## Как работает

**1. Базовый каталог `movies.json`.**
- Топ-150 Кинопоиска по числу голосов (`sortField=votes.kp`, `sortType=-1`): фильмы, мультфильмы и аниме (`type=movie|cartoon|anime`), без сериалов. Формат — массив `Movie` (тот же `Codable`, что в `AppData`).
- Лежит ресурсом пакета: `Packages/OneToOneKit/Sources/MovieAPI/Resources/movies.json`, читается через `Bundle.module`. Так его видят и приложение, и `swift test` (**решение Claude**).
- В первом PR файл собран из того, что есть без ключа: пустой массив `[]` или маленький тестовый набор. Настоящий топ-150 — после запуска скрипта с ключом (**решение Claude**: у Claude нет ключа Кинопоиска).

**2. Скрипт обновления.**
- Исполняемая цель пакета `UpdateMovies`: `cd Packages/OneToOneKit && swift run UpdateMovies`. Использует тот же `KinopoiskCatalog`, поэтому формат и фильтры совпадают с приложением (**решение Claude**: shell + `jq` не у всех стоит).
- Ключ берёт из переменной `KINOPOISK_API_KEY` или из `Config/Secrets.xcconfig`. 3 страницы по 50 = 3 запроса.
- Пишет `movies.json` отсортированным по `id`, чтобы diff в git был читаемым.

**3. Кэш на телефоне.**
- Отдельный JSON в Application Support (`MovieCatalogCache.json`), не в `AppData` (**решение Claude**: это не данные пары, в iCloud не нужен).
- Хранит фильмы, дату последней догрузки и номер следующей страницы топа.
- Туда попадает всё, что вернули `search`, `recommendations`, `discover` и догрузка. Повторный фильм обновляет запись (свежие рейтинги), дублей нет.
- Не больше 2000 фильмов (~1 МБ); при переполнении выкидываются самые давние по времени добавления (**решение Claude**).

**4. Догрузка раз в день.**
- При открытии колоды, если с последней догрузки сменился календарный день: 1 запрос — следующая страница топа (50 фильмов), 1 запрос — новинки текущего года (`year=<год>`, по голосам).
- Ошибка (нет сети, лимит) — дата не сдвигается, попробуем в следующий раз.
- Догрузка не задерживает колоду: идёт параллельно с рекомендациями, а её результат попадает в кэш (**решение Claude**).

**5. Колода.**
- Как сейчас: «похожие» на 5 фильмов + подборка по жанрам из сети.
- Плюс всегда: фильмы из базы и кэша с жанром настроения, по убыванию рейтинга Кинопоиска, до 40 штук. Идут после сетевых рекомендаций (**решение Claude**: с сетью добавляют разнообразия, без сети — единственный источник). Дубли и лимит 40 убирает `DeckBuilder`, просмотренные и свайпнутые — как раньше.
- Запросов к Кинопоиску на подбор не больше, чем сейчас (6), плюс не больше 2 в день на догрузку.

## Устройство (имена — на усмотрение плана)
- `MovieAPI`: локальный каталог (база + кэш, выбор по жанрам), хранилище кэша (файл), обёртка над `KinopoiskCatalog`, которая кладёт ответы в кэш, догрузка (новые запросы «топ, страница N» и «новинки года» в `KinopoiskCatalog`).
- `DeckLoader.recommendations` получает фильмы локального каталога и добавляет их в конец.
- Приложение: один общий экземпляр каталога на всё приложение (сейчас `@Entry` создаёт `KinopoiskCatalog` заново), `AppModel.deck` берёт локальные фильмы.

## Тесты
- Чтение базы `movies.json` из ресурсов.
- Слияние кэша с базой без дублей, обновление записи, предел 2000.
- Выбор по жанрам без сети: только подходящие жанры, по рейтингу, не больше 40.
- Колода без сети и при 401/403: собирается из списков и локального каталога.
- Догрузка: не чаще раза в календарный день, ошибка не сдвигает дату, номер страницы растёт.
- Обёртка кладёт в кэш ответы `search`, `recommendations`, `discover`.
