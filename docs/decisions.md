# Журнал решений

Одна строка на решение: дата, что решили, почему.

- 2026-10-10: Стек SwiftUI, только iOS. Цель: App Store, Android не планируем.
- 2026-10-10: Репозиторий `docomoz/one-to-one`, в `main` только через PR. (Сначала был приватным, см. ниже.)
- 2026-10-10: Ревью напарника не делаем, обсуждаем голосом. Автор вливает свой PR сам после `/code-review` и зелёных проверок.
- 2026-10-10: Задачи ведём в GitHub Issues и на доске GitHub Project; кто взял задачу, ставит себя assignee.
- 2026-10-10: Тяжёлые задачи (оркестрация, большие ревью, субагенты) ведём на тарифе Max у Максюши, на Pro у Дарьи задачи поменьше.
- 2026-10-10: Версия 1 — только выбор фильма свайпами и трекер (секс, оргазмы, цикл). Календарь, вишлист, выходные, заметки — следующие версии. Причина: это то, ради чего мы откроем приложение каждый день.
- 2026-10-10: Пара — ровно двое, мужчина и женщина, пол выбирается при создании пары. Цикл ведёт женщина, мужчина видит упрощённый вид и подсказку дня.
- 2026-10-10 (заменено 2026-10-11, см. «свой сервер Appwrite»): Синхронизация и аккаунты через iCloud (CloudKit). Причина: без своего сервера, бесплатно, данные видят только двое; оба на iPhone.
- 2026-10-10: Свайпы фильмов асинхронные: каждый свайпает, когда удобно, совпадение — когда лайкнули оба. Причина: удобнее и не требует синхронизации в реальном времени.
- 2026-10-10: ~~Фильмы: каталог и рекомендации TMDB, рейтинг IMDb через OMDb, Кинопоиск через неофициальный API.~~ Заменено решением ниже.
- 2026-10-10: Фильмы без TMDB: каталог, постеры, «похожие» и рейтинги берём из Кинопоиска (неофициальный API poiskkino.dev, бывший kinopoisk.dev), OMDb только как запас для рейтинга IMDb. Причина: одного русского каталога хватает, на один ключ и один сервис меньше.
- 2026-10-10: Дизайн свой и яркий (направление B «Яркий градиент», по мотивам Instagram), управление привычное, как в родных приложениях iPhone. Причина: антицель — «криво и хуже стандартных приложений».
- 2026-10-10: Минимальная версия iOS 26. Причина: свежий SwiftUI, у нас новые iPhone.
- 2026-10-10: Xcode-проект описываем в `project.yml` и генерируем XcodeGen, сам `.xcodeproj` в git не храним. Причина: двое правят проект параллельно, а текстовый файл почти не даёт конфликтов.
- 2026-10-10: Вся логика лежит в локальном Swift-пакете `OneToOneKit`, экраны — в приложении. Причина: быстрые тесты через `swift test` без симулятора, проще TDD.
- 2026-10-10 (заменено 2026-10-11, см. «свой сервер Appwrite»): До iCloud данные хранятся одним JSON-файлом `AppData` на телефоне, синхронизация позже через `CKSyncEngine`. Причина: можно строить и тестировать всё до Apple Developer.
- 2026-10-10: Bundle id приложения `com.docomoz.onetoone`. Причина: к нему потом привязывается контейнер iCloud, менять его после запуска нельзя. Команду для подписи каждый пишет в свой `Config/Secrets.xcconfig`, в git её нет.
- 2026-10-10: Проверки на GitHub (CI) на раннере `macos-26` с закреплённым Xcode 26.6. Причина: обновление образа не должно внезапно ломать сборку; версию меняем отдельным PR.
- 2026-10-10: Репозиторий `docomoz/one-to-one` публичный, `main` защищён: только через PR с зелёной проверкой `ci`, без force push, правило действует и на владельца. Причина: на бесплатном тарифе защита веток доступна только публичным репозиториям, а macOS-минуты для них бесплатные.
- 2026-10-10: `AppModel.data` снаружи только для чтения, менять данные можно только через `model.update { … }`. Причина: так каждое изменение гарантированно сохраняется на диск. Новое поле в `AppData` добавляем и в его `init(from:)` со значением по умолчанию, чтобы старые файлы читались.
- 2026-10-10: CI собирает приложение и его тесты без симулятора (`build-for-testing`), тесты пакета идут только через `swift test`, тесты приложения запускаем локально. Причина: загрузка симулятора на раннере занимала 85–95% времени CI (до 12 минут); вернём их в CI, когда появятся настоящие тесты экранов.
- 2026-10-10: Первая строка описания PR `Closes #N`, а не «Закрывает #N». Причина: GitHub закрывает issue после merge только по английским словам (close, fix, resolve), PR #33 с «Закрывает #12» задачу не закрыл.
- 2026-10-10: При знакомстве спрашиваем дату рождения обоих (`Person.birthDate`, день как `DayKey`). Причина: персонализация потом: поздравление с днём рождения, возраст, анализ цикла и статистики по возрасту.
- 2026-10-10: Приложением можно пользоваться с 18 лет: знакомство не пускает дальше, если кому-то из пары меньше 18. Причина: приложение про интимную жизнь, в App Store у него рейтинг 18+.
- 2026-10-10: Расчёт цикла не учитывает отметки месячных позже сегодняшнего дня. Причина: случайная отметка в будущем иначе ломает день цикла и прогноз; планировать месячные отметками не нужно, для этого есть прогноз.
- 2026-10-10: Отметки месячных с промежутком до 10 дней считаются одними месячными. Причина: забытый день посреди месячных иначе начинает новый цикл и сбивает прогноз. Среднюю длину считаем как в плане: по всем промежуткам, потом ограничиваем 21–40.
- 2026-10-10: Проверки на GitHub (CI) не запускаем, если в PR поменялись только `.md` и файлы в `docs/`. Причина: на сборку они не влияют, а macOS-минуты дорогие.
- 2026-10-10: Каталог фильмов берёт с Кинопоиска фильмы, мультфильмы и полнометражное аниме (`type=movie`, `cartoon`, `anime`, без `isSeries`), сериалы и шоу отбрасывает. Причина: у Кинопоиска мультфильмы и аниме отдельные типы, без них настроение «Что-то лёгкое» (жанр «мультфильм») почти ничего не находит.
- 2026-10-10: Запись секса хранит только день (`DayKey`), без времени; за день может быть сколько угодно записей, каждая — отдельный раз, а в серию день идёт один раз. Причина: время нам не нужно, а без него запись не съезжает на соседний день из-за часового пояса.
- 2026-10-10: В календаре цикла она отмечает симптомы на любой день: 10 готовых («Болит голова», «Тянет живот»…) и свои текстом. Симптомы видит только она, в упрощённом виде для него их нет. Причина: Дарья попросила при обсуждении #16; свои симптомы запоминаются из уже поставленных, отдельный список не храним.
- 2026-10-10: Защита `main` требует, чтобы ветка PR была свежей (включает последний `main`) и проверка `ci` прошла на ней. Причина: #41 и #42 по отдельности были зелёными, а вместе сломали сборку. Задание `ci` для PR только с документами пропускается, а не отключается, иначе обязательная проверка не придёт и PR не вольётся.
- 2026-10-10: У Даши нет ссылки «Что видит он» (подсказка Максюши), хотя в спецификации она была. Причина: при обсуждении #17 решили, что и так всё рассказываем и показываем друг другу.
- 2026-10-10: В его календаре каждый день закрашен мягким цветом фазы (месячные розовый, фолликулярная оранжевый, овуляция фиолетовый, лютеиновая синий), будущие — по прогнозу; дни не нажимаются. Подсказка без отметок цикла не помечается как прогноз. Причина: так попросили при обсуждении #17, а остальное — решение Claude.
- 2026-10-10: Язык разработки приложения русский: `options.developmentLanguage: ru` в `project.yml`, без `ru.lproj` и `CFBundleAllowMixedLocalizations`. Причина: ключ `developmentRegion` XcodeGen молча игнорировал, в `Info.plist` был `en`, и системные строки UIKit (меню «Вырезать / Скопировать» в полях ввода и т. п.) шли по-английски. `.environment(\.locale, ru_RU)` в `OneToOneApp` переводит только то, что рисует SwiftUI (даты, «Поиск»), поэтому нужны оба.
- 2026-10-10: Ключ Кинопоиска попадает в приложение через `Info.plist` (ключ `KinopoiskAPIKey` = `$(KINOPOISK_API_KEY)` из `Secrets.xcconfig`); `Config/Info.plist` генерирует XcodeGen из `project.yml`, в git его нет. Причина: при `GENERATE_INFOPLIST_FILE` свои ключи через `INFOPLIST_KEY_…` не добавить, а ключ в коде попал бы в публичный репозиторий.
- 2026-10-10: В репозитории включено автослияние, PR ставим на него сразу после открытия (`gh pr merge --squash --delete-branch --auto`). Причина: Claude в приложении не может сам следить за `ci`, а так GitHub вливает PR сам, когда проверки зелёные; защита `main` (свежая ветка, зелёная `ci`) остаётся.
- 2026-10-10: На главной нет «ближайших планов»: календарь пары не входит в v1, планы появятся вместе с ним. Годовщина — отдельной задачей позже.
- 2026-10-10: Рекомендации без жанров («похожие» Кинопоиска, поле `similarMovies`, приходят без `genres`) идут в колоду на своём месте среди рекомендаций, а не отбрасываются; «похожие» стоят раньше подборки по жанрам. Совпадение считается по последнему свайпу каждого: передумал — считается новое решение. Причина: иначе фильтр по настроению выкидывал все «похожие», а дозапрос жанров стоил бы запрос на каждый фильм из 200 в день.
- 2026-10-10: Подбор фильма общий на двоих: текущий — последний начатый, пока не нажали «Смотрим» на фильме, которому в нём поставили ♥; новый подбор заменяет старый. На вкладке «Фильмы» сверху карточка вечера: «Что смотрим сегодня?», «{партнёр} уже свайпает. Ваша очередь» или «Совпали: N»; кнопка «Выбрать фильм» на главной открывает то же. Запросы к Кинопоиску сдаются через 10 секунд, чтобы колода не ждала минуту и строилась из списков. Причина: так второй присоединяется к подбору без уведомлений (они в #26) и без нового поля в данных; решение Claude при обсуждении #23, поменяем, когда попользуемся.
- 2026-10-10: Иконка приложения — файл Icon Composer `App/OneToOne/AppIcon.icon` (два сердечка без лиц, розовое и синее, в духе «Любви с первого взгляда», на фирменном градиенте), слои — SVG, нарисованные вручную; в тёмной теме свои SVG с обводкой цветом градиента. Причина: для iOS 26 это родной формат Apple — «жидкое стекло», тёмный и тонированный варианты iOS строит сама; без зависимостей. Фон-градиент только из двух цветов (оранжевый → фиолетовый) и всегда сверху вниз: больше Icon Composer не позволяет, направление для фона он не учитывает. Форма и место сердца повторяются в четырёх SVG (светлый и тёмный вариант каждого): меняя форму, правьте все четыре. Превью из файла: `ictool` внутри Icon Composer.app.
- 2026-10-10: Годовщина: дата «вместе с» хранится в `AppData.togetherSince` и вводится на экране «Пара» (шестерёнка на главной); на главной обе плашки — день рождения и годовщина, ближайшая сверху, в один день — день рождения. Причина: дату пользователь стал бы искать в настройках пары, а на главной хочет видеть и день рождения, и годовщину; решено на брейншторме #58.
- 2026-10-10: Риск беременности считаем календарным методом (Огино–Кнаус), низкий только при ≥3 циклах с разбросом ≤10 дней, „безопасных“ дней не показываем. Причина: прогноз не знает настоящую овуляцию, обещать безопасность нечестно.
- 2026-10-10: Офлайн-каталог фильмов: в пакете лежит `movies.json` (топ-150 Кинопоиска, обновляет `swift run UpdateMovies` с ключом), а всё, что пришло от Кинопоиска, телефон запоминает в отдельном файле `MovieCatalogCache.json` (не в `AppData`, в iCloud не едет; до 2000 фильмов, вытесняются самые давние). Раз в день — 2 запроса: следующая страница топа и новинки года; день засчитывается, если пришёл хоть один ответ; пока база пустая, догрузка идёт с первой страницы топа. В колоду всегда добавляются фильмы с телефона по жанрам настроения (по рейтингу Кинопоиска, до 40) после сетевых рекомендаций. Причина: колода собирается без сети и после лимита 200 запросов в день, при этом запросов на подбор не больше, чем было; решили при обсуждении #55.
- 2026-10-10: Пока месячные задерживаются, в будущих днях календаря нет низкого риска: окно по прогнозу остаётся высоким, остальное — «средний, задержка». Причина: без заворота сегодня задержка, а завтра по прогнозу «низкий» — пустой день в календаре выглядел бы разрешением; нашлось на ревью #65.
- 2026-10-10: Оценка просмотренных фильмов: плашка 👍 / 👎 / ✕ под карточкой вечера со следующего дня после «Смотрим», каждый за себя. 👍 делает фильм затравкой «похожих» (👍 от обоих — первой), 👎 убирает «похожие» на 3 последних таких фильма из рекомендаций (не из списков), жанры не трогаем. Причина: подбор подстраивается под вкус без лишних запросов (до 9 на подбор) и не навязывает оценку; решили при обсуждении #56.
- 2026-10-11: Сетка календаря цикла (`MonthGridView`) растёт со шрифтом только до `.xxxLarge`, круг числа — до 38 pt (с кольцом выбора 44 pt, колонка iPhone SE); шапка месяца, легенды и карточка дня растут без предела, легенда фаз на размерах Универсального доступа в одну колонку. Причина: семь колонок по ~45 pt на iPhone SE и iPhone 17, крупнее «28» и «Пн» в них не помещаются, а VoiceOver и карточка дня дают полную дату крупно; решено на брейншторме #72.
- 2026-10-11: На «Главной» на размерах Универсального доступа плитки (статистика и кнопки) в одну колонку; карточки ниже (подсказка у него, «Сегодня» у неё, дни рождения и годовщина) растут со шрифтом только до `.accessibility2`, предел на всю карточку. Причина: в полширины рвётся «Оргазм/ы», а «Фолликулярная», «Комплимент» и «годовщиной!» крупнее не влезают в ширину карточки на iPhone SE (311 pt) и рвутся посреди слова; заголовок карточки не должен стать крупнее текста; нашлось после #72, задача #76.
- 2026-10-11: Аккаунты, пары и синхронизация через свой сервер Appwrite (своя установка в Timeweb Cloud, российский дата-центр) вместо iCloud, записи пары со сквозным шифрованием: ключ пары только на устройствах, передаётся новому устройству обменом ключами со сверкой 6-значного кода, восстановление через партнёра. Причина: приложение для всех в магазинах и на Android, вебе, компьютерах, данные россиян по 152-ФЗ в России, интимные данные не должны быть доступны даже нам. Дизайн: `docs/superpowers/specs/2026-10-11-own-backend-design.md`, план: `docs/superpowers/plans/2026-10-11-own-backend.md`.
- 2026-10-11: Сервер Appwrite 2.4.0 в Timeweb Cloud, Санкт-Петербург, 2 vCPU / 2 ГБ + swap 4 ГБ; до публикации адрес `api.194-87-44-100.sslip.io` и письма с кодами через SMTP Gmail. Перед публикацией — свой домен, отправитель писем на нём (Unisender Go), 4 ГБ RAM, дамп базы в S3. Причина: на время разработки не платим за то, что нужно только к выходу; в Москве не было мест, Питер — тоже Россия. Подробности: `docs/server.md`.
- 2026-10-11: Функции сервера на Node.js 22 с официальным SDK `node-appwrite` 29.2.0 (версия закреплена точно, `package-lock.json` в git). Причина: это серверный SDK Appwrite для ответа в формате 2.0.0, как у нашего Appwrite 2.4.0; рантайм `node-22` уже включён на сервере. Тесты на встроенном `node:test` с фейковым Appwrite, без других зависимостей.
- 2026-10-11: Схема сервера описана таблицами (`tablesDB` / `tables` / `columns` в `Server/appwrite.config.json`), а не коллекциями; строки — `varchar` и `text`, а не устаревший `string` (кроме перечисления `status`: CLI описывает его как `string` с `format: enum` и создаёт отдельной колонкой-enum). Причина: в Appwrite 2.x коллекции переименованы в таблицы, а Appwrite CLI 28 пишет и читает конфиг в этом виде.
- 2026-10-11: «В другой паре» для `accept-invite` — в команде, где кроме вызывающего есть кто-то ещё. Своя пара без партнёра (так пользуются приложением в одиночку) вход по коду не блокирует, из неё приложение выходит само через `leave-couple` после входа в новую. Причина: иначе одиночке пришлось бы сначала удалить свою пару с данными, и при ошибке в коде он остался бы ни с чем.
- 2026-10-11: Просроченные приглашения и запросы ключа удаляет функция `cleanup-expired` раз в сутки, а также попутно `create-invite` и `accept-invite`. Причина: иначе они копились бы на сервере без срока (замечание юридического ревью #92).
- 2026-10-11: Шифрование пары по `docs/crypto.md`: записи — ключом пары напрямую (AES-256-GCM, AAD `coupleID/documentID`), завёрнутый ключ — в том же конверте с версией, AAD — открытые ключи отправителя и получателя, проверочный код — первые 4 байта SHA-256 big-endian по модулю миллиона. Векторы сверены с `node:crypto`. Причина: всё повторяется стандартными библиотеками Android и веба; AAD с ключами привязывает ключ к сверенному коду. Код без обязательства (commitment) сервер может подобрать перебором, поэтому в задачах 2 и 8 нужен шаг с обязательством (описан в `docs/crypto.md`), а движок (задача 5) должен шифровать `updatedAt` и удаление внутри конверта.
