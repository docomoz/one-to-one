# one-to-one

iOS-приложение для пар (можно пользоваться и одному): заметки, календарь и всё нужное в одном месте. Делаем вдвоём (Дарья и Максюша), каждый со своим Claude Code. Опыта программирования у нас нет: объясняй коротко и по делу.

## С чего начинать каждый чат
1. `git pull` на `main`, затем своя ветка.
2. Прочитать задачу (issue), на которую ссылается пользователь.
3. По необходимости: `docs/spec.md` (что строим), `docs/plan.md` (как строим), `docs/decisions.md` (уже принятые решения). Не читай всё подряд, только нужное для задачи.

## Стек
- SwiftUI, только iOS. Минимальная версия iOS: решим в `docs/decisions.md`.
- Бэкенд с аккаунтами и синхронизацией пары: выбираем на этапе спецификации.
- Сборка и тесты: команды допишем, когда появится Xcode-проект.

## Как работаем
- Одна задача = один issue = одна ветка = один PR. Ветки: `feat/…`, `fix/…`, `chore/…`, `docs/…`.
- В `main` только через PR. Напрямую в `main` не пушим.
- Коммиты маленькие и осмысленные, сообщения на русском в повелительном наклонении («Добавить экран заметок»).
- Перед PR: сборка и тесты проходят, `/code-review` прогнан, найденные проблемы исправлены.
- Ревью напарника не ждём, всё обсуждаем голосом. Когда PR открыт и проверки зелёные, сам вливай его: `gh pr merge --squash --delete-branch`. Если есть конфликт с `main`, сначала подтяни `main` и разреши его.
- В описании PR: что сделано, как проверить, что осталось. Это передача контекста напарнику.
- Принятое решение (библиотека, архитектура, отказ от фичи) записываем одной строкой в `docs/decisions.md` с причиной.
- Новые фичи и изменения поведения: сначала скил brainstorming, потом writing-plans, потом TDD (Superpowers).

## Режим обучения
Когда делаешь что-то неочевидное, добавь одну строку «💡 Принцип: …» о том, почему так лучше. Не больше 1–2 на ответ.

## Код
- Маленькие файлы с одной ответственностью. Вью отдельно от логики и данных.
- Не добавляй зависимости без записи в `docs/decisions.md`.
- Секреты и ключи никогда не коммитим.
